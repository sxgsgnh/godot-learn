🔑 主题系统的三大支柱
================================================================================

1. Theme资源 (scene/resources/theme.*)
   ├─ 存储样式数据的Resource子类
   ├─ 六种数据类型: 颜色、常量、字体、字体大小、图标、样式框
   ├─ 支持默认值(default_font, default_font_size等)
   └─ 内部使用6个HashMap<StringName, ThemeXxxMap>组织数据

2. ThemeDB (scene/theme/theme_db.*)
   ├─ 全局单例，管理engine和project主题
   ├─ 维护通用fallback值(最后的兜底)
   ├─ 创建和管理ThemeContext
   ├─ 绑定GUI类的主题项到缓存系统
   └─ 在引擎启动时initialize_theme()

3. ThemeOwner (scene/theme/theme_owner.*)
   ├─ 追踪主题所有权关系
   ├─ 实现主题从父节点到子节点的级联继承
   ├─ 处理主题变更的通知和传播
   └─ 管理主题查询的fallback链

🎯 关键特性和机制
================================================================================

1. 变更信号机制
   ├─ Theme._emit_theme_changed() 发出changed信号
   ├─ Control._theme_changed() 监听并响应
   ├─ ThemeOwner.propagate_theme_changed() 传播到子树
   └─ NOTIFICATION_THEME_CHANGED通知所有受影响控件

2. 缓存优化系统
   ├─ Control内部维护theme_icon_cache等6个缓存
   ├─ 第一次查询时填充缓存
   ├─ NOTIFICATION_THEME_CHANGED时清除缓存
   └─ 避免频繁的哈希表查找

3. 分层继承结构
   ├─ Override > 本节点 > 父节点 > 祖父节点 > ... > 全局 > Fallback
   ├─ 每层可以覆盖上一层
   ├─ 支持部分覆盖(某些项目不设置)
   └─ 自动fallback到下一层

4. 类型变体系统
   ├─ 允许为同一控件类型定义多个样式预设
   ├─ 例如: Button_success, Button_danger等
   ├─ 变体继承基础类型，可选择性覆盖
   └─ 通过Control.set_theme_type_variation()激活

5. 主题上下文隔离
   ├─ ThemeContext支持嵌套和隔离
   ├─ 编辑器和游戏主题分离
   ├─ 可创建子上下文进行主题隔离
   └─ _propagate_theme_context()处理传播

📋 Theme加载的完整流程
================================================================================

启动阶段:
1. ThemeDB::initialize_theme()
   └─ 读取gui/theme/custom (project_theme路径)
   └─ 读取gui/theme/custom_font (project_font路径)
   └─ ResourceLoader::load() 加载主题文件
   └─ ThemeDB::set_project_theme()
   └─ make_default_theme() 生成引擎默认主题
   └─ _init_default_theme_context()
      └─ 创建default_theme_context
      └─ 堆栈主题: [project_theme, default_theme]

运行时加载:
1. Control进入场景树
   └─ NOTIFICATION_ENTER_TREE
   └─ set_theme_context()
   └─ 获取nearest theme context (向父节点查找)
   └─ NOTIFICATION_THEME_CHANGED
   └─ _invalidate_theme_cache()
   └─ _update_theme_item_cache()
   └─ queue_redraw()

2. 动态设置主题
   └─ Control::set_theme(theme)
   └─ 连接theme->changed信号
   └─ ThemeOwner::propagate_theme_changed()
      └─ 遍历整个子树
      └─ 对每个节点发送NOTIFICATION_THEME_CHANGED
      └─ 清除缓存并重建

🔄 Theme变更的传播过程
================================================================================

修改主题项目时:
1. theme->set_color("font_color", "Button", Color.WHITE)
   │
   ├─ 验证项目和类型名称合法性
   ├─ 断开旧颜色资源的changed信号
   ├─ icon_map["Button"]["font_color"] = new_value
   ├─ 连接新颜色资源的changed信号 (如果资源会变)
   │
   └─ _emit_theme_changed(true)
      └─ 检查no_change_propagation标志
      └─ notify_property_list_changed() (如果是新项)
      └─ emit_changed()  ← 所有观察者收到此信号

观察者响应:
2. Control._theme_changed()
   │
   └─ if (is_inside_tree())
      │
      └─ ThemeOwner::propagate_theme_changed(this, this, true, false)
         │
         └─ 向子树发送NOTIFICATION_THEME_CHANGED
            │
            ├─ _invalidate_theme_cache()  // 清除缓存
            ├─ _update_theme_item_cache() // 重建缓存
            ├─ queue_redraw()             // 标记重绘
            ├─ update_minimum_size()      // 更新尺寸
            └─ emit_signal("theme_changed") // GDScript通知

🌳 Control节点的主题查询流程
================================================================================

control->get_theme_color("font_color"):
│
├─ Step 1: 检查override
│  └─ if (p_theme_type == get_class_name())
│     └─ return theme_color_override.get(p_name)  // 命中就返回
│
├─ Step 2: 查询本地缓存
│  └─ if (theme_icon_cache[p_theme_type][p_name])
│     └─ return cached_value  // 命中就返回
│
├─ Step 3: 构建类型依赖链
│  └─ ThemeOwner::get_theme_type_dependencies()
│     └─ 对Button_success返回: ["Button_success", "Button"]
│
├─ Step 4: 在节点及祖先中查询
│  └─ ThemeOwner::get_theme_item_in_types()
│     │
│     └─ for (Node *owner in [本节点, 父主题, 祖父主题, ...])
│        │
│        └─ for (StringName type in ["Button_success", "Button"])
│           │
│           └─ Ref<Theme> theme = owner.get_theme()
│              └─ if (theme.has_color(name, type))
│                 └─ return theme.get_color(name, type)  // 找到了!
│
├─ Step 5: 查询全局主题上下文
│  └─ ThemeContext *context = _get_active_owner_context()
│     │
│     └─ for (Ref<Theme> theme : context->get_themes())
│        └─ if (theme.has_color(name, type))
│           └─ return theme.get_color(name, type)
│
└─ Step 6: 返回fallback值
   └─ return context->get_fallback_theme()
      →get_theme_item(DATA_TYPE_COLOR, name, StringName())

⚡ 性能优化的关键点
================================================================================

1. 批量操作时冻结变更信号
   theme->_freeze_change_propagation();
   for (...) theme->set_color(...);  // 不发出信号
   theme->_unfreeze_and_propagate_changes();  // 一次性发出

2. 缓存机制
   ✓ 自动缓存，无需手动处理
   ✓ NOTIFICATION_THEME_CHANGED时清除
   ✓ 下次查询时重建

3. 避免频繁替换主题
   ✓ 启动时设置好，不要每帧改变
   ✓ 如需改变项目，modify主题而不是替换
   ✓ 全局主题改变会通知所有控件

4. 主题层级不要太深
   ✓ 在顶层设置主题，让子节点继承
   ✓ 避免过多中间节点设置主题
   ✓ 减少查询链的长度

📐 全局主题应用的完整链路
================================================================================

编辑器启动 → gui/theme/custom读取 → ResourceLoader加载
   ↓
ThemeDB::set_project_theme(loaded_theme)
   ↓
default_theme_context->set_themes({project_theme, default_theme})
   ↓
ThemeContext连接所有主题的changed信号
   ↓
任何主题改变 → ThemeContext._emit_changed() → context.changed信号
   ↓
所有Control连接了context.changed信号
   ↓
ThemeOwner::_owner_context_changed()
   ↓
if (is_inside_tree()) notification(NOTIFICATION_THEME_CHANGED)
   ↓
整个场景树的所有Control重新加载主题

🎨 类型变体的应用示例
================================================================================

定义:
theme.set_type_variation("Button_success", "Button")
theme.set_color("font_color", "Button_success", Color.GREEN)

使用:
button.theme_type_variation = "success"

查询时:
1. 查找"Button_success"类型的font_color
2. 如果没找到，查找"Button"类型的font_color
3. 如果都没找到，查找fallback

效果:
✓ success按钮使用绿色文字(override)
✓ 其他样式继承自Button(inherit)
✓ 灵活且高效

🔧 编辑器vs项目主题
================================================================================

初始化逻辑:
#ifdef TOOLS_ENABLED
if (is_editor_hint()) {
    // 编辑器模式: 只使用default_theme
    themes = [default_theme]
} else {
    // 项目运行: 使用project_theme + default_theme
    themes = [project_theme, default_theme]
}
#else
// 导出后: 始终使用project_theme + default_theme
themes = [project_theme, default_theme]
#endif

结果:
├─ 编辑器中: 使用编辑器主题风格
├─ 运行项目: 使用project_theme定义的风格
└─ 导出游戏: 使用project_theme定义的风格

📝 使用建议总结
================================================================================

✓ 在启动时设置主题，不要频繁改变
✓ 使用类型变体定义多个样式，不要定义新类型
✓ 在根节点设置主题，让子节点自动继承
✓ 使用批量操作的freeze/unfreeze优化性能
✓ 在_ready()或theme_changed中缓存主题值
✓ 监听theme_changed信号处理主题相关的更新
✓ 使用项目设置(gui/theme/custom)配置全局主题
✗ 避免频繁修改主题项目
✗ 避免中间节点过多设置主题
✗ 避免在_process中访问主题
